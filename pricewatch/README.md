# 📉 가격 추적기

감시 목록의 상품 가격을 6시간마다 확인해서, **평소보다 확실히 싸진 것만** GitHub 이슈로 알려 줍니다.
폰에서 이슈 하나 열면 상품이 등록되고, 그 뒤로는 알아서 돕니다.

서버도 데이터베이스도 없습니다. GitHub Actions가 돌고, 가격 기록은 이 저장소 안의
JSON 파일 하나(`data/history.json`)에 쌓입니다.

## 쓰는 법

**상품 등록** — Issues → New issue → **「가격 감시 추가」** 에 상품 주소를 붙여넣고 제출.
1분 뒤 목록에 들어가고, 지금 가격이 얼마인지 답글이 옵니다.

**알림** — 조건에 맞는 하락이 생기면 **「📉 가격이 떨어진 상품」** 이슈가 열립니다.
읽고 닫으시면 됩니다. 떨어진 게 없으면 아무 일도 일어나지 않습니다.

**빼기** — `config.json` 의 `watch` 목록에서 그 줄을 지우면 됩니다.

## 무엇을 "싸졌다"고 보는가

이게 이 프로그램의 전부입니다. 규칙은 [`scripts/detect.mjs`](./scripts/detect.mjs) 한 곳에 있습니다.

- **기준가는 그 상품 자신입니다.** 판매 페이지에 적힌 "정가"는 믿지 않습니다.
  최근 30일 동안 이 상품이 실제로 달고 있던 가격의 중앙값이 기준가입니다.
- **오래 붙어 있던 가격이 더 무겁습니다.** 기록은 가격이 바뀐 순간만 남기는데,
  그대로 세면 한 달 내내 붙어 있던 가격과 하루짜리 반짝 가격이 똑같은 한 표가 됩니다.
  그래서 기록을 하루 단위로 펴서(그날 실제로 붙어 있던 가격) 셉니다.
- **기준가보다 15% 이상 쌀 때** 알립니다. 그때까지 본 최저가면 🔻 표시가 붙습니다.
- **등록 직후에는 안 알립니다.** 최소 2일은 지켜본 뒤부터 판단합니다 —
  기준가를 낼 근거가 없는 상태에서 "싸다"고 말할 수는 없으니까요.
- **같은 가격으로 3일 안에 두 번 알리지 않습니다.** 더 떨어지면 그때 다시 알립니다.

숫자는 전부 `config.json` 의 `alert` 에서 바꿉니다:
`baselineDays`(기준 기간) · `dropPercent`(하락 기준) · `minDays`(최소 관찰) ·
`cooldownDays`(재알림 간격).

## 못 하는 것

- **가격을 페이지에서 못 읽는 상품이 있습니다.** 상품 페이지의 공개 정보(OG 태그,
  JSON-LD)를 읽는 방식이라, 로그인해야 보이거나 자바스크립트로 나중에 그리는 가격은
  못 가져옵니다. 그런 상품은 실행 요약에 "확인하지 못한 상품"으로 계속 뜨니
  목록에서 빼세요.
- **최저가 비교가 아닙니다.** 여러 쇼핑몰 값을 비교하는 게 아니라, 등록한 그 페이지의
  가격이 그 페이지의 평소보다 싼지를 봅니다.
- **읽은 값은 표시가일 뿐입니다.** 쿠폰·카드할인·배송비는 모릅니다. 사기 전에 실제
  결제 금액을 확인하세요.
- 상품 하나당 6시간에 한 번, 상품 페이지 한 장만 읽습니다. 각 쇼핑몰의 이용약관을
  확인하고 쓰세요.

## 파일

| 파일 | 하는 일 |
|---|---|
| `config.json` | 감시 목록과 판정 기준 |
| `data/history.json` | 가격 기록. 가격이 움직인 순간만 쌓입니다 |
| `scripts/check.mjs` | 6시간마다: 훑고 → 기록하고 → 떨어진 것만 이슈로 |
| `scripts/detect.mjs` | "싸졌는가" 판정 규칙 |
| `scripts/meta.mjs` | 상품 페이지에서 지금 가격 읽기 |
| `scripts/add.mjs` | 이슈 폼으로 들어온 상품을 목록에 넣기 |
| `../.github/workflows/pricewatch.yml` | 위 두 가지를 실행하는 워크플로 |
